# Does LLM2Vec improve SLICE chunk features on the existing Numina split?

**Not measured yet.** Three arms use the same saved Numina answers and chunk
boundaries: causal Qwen, unadapted official bidirectional Qwen, and Qwen adapted
with official MNTP then SimCSE. Every arm learns a fresh SLICE and one Ridge head.
This is offline final-outcome prediction, not PPO improvement or MC state-value MAE.

## What stays the same

- Existing Numina train/validation/test question assignments from
  `outputs/numina-no-folds-v1`; no new split or downloaded benchmark.
- Saved verified answers from `outputs/fixed-policy-critics-v1`. These were
  generated by one predeclared trained SLICE/token actor. All three arms use
  identical answers, original token IDs, rewards and MATH chunk starts (fallback
  32). Parse failures remain reward zero, under the source verifier convention.
- SLICE calls the existing package `_fit_compressor`, Bottleneck and encoder:
  five blocks [27,26,24,20,12], RMS block normalization, training-only coordinate
  centering/single scalar scaling, 768 unit-row-projection ReLU features,
  correctness BCE + .01 mean activation penalty, AdamW LR .0003 and weight decay
  .001, batch 2048, 30 epochs selected by validation sigmoid Brier.
- Up to eight training/validation chunk prefixes per answer train/select SLICE;
  Ridge accumulates **all training chunk states**, adds an intercept, and solves
  one 769-dimensional raw-sum system with epsilon .01. No folds, replay, sample
  normalization, output LayerNorm, calibration or clipping is added.

The offline head uses the same accumulation mathematics, but has no PPO updates.
PPO integration and the eventual one-head cumulative online loop are subsequent
work. Do not describe this result as a changed PPO recipe or a PPO winner.

## Data and controls

Main: 500 training questions × four answers, 100 validation × four answers,
50 test × one answer, all available chunk starts. This **reuses a subset of our
existing Numina split**, not the whole original online training/test population.
The smoke uses 8/4/4 questions, two adaptation steps and two compressor epochs.
Source identity, question split/reference agreement, saved answer hashes, base
model identity, code identity and passed unpadded sanity are checked before work.
No original SLICE checkpoint is reused because coordinates change.

All arms use BF16 and the same official FlashAttention backend, last-prefix-token
block readout and unpadded individual-prefix extraction. Thus new causal numbers
are the matched control; historical FP32 studies provide context, not an exact
reference leaderboard. Same chunker does not remove its documented future-text
boundary-selection limitation; features are physically truncated before the chunk.

Three compressor seeds (42–44) in main; **one actor and one encoder-adaptation
seed**, not three independent RL or adaptation runs. Main recipes are fixed
before test evaluation. Bootstrap contrasts resample compressor seeds/questions
and are exploratory/unadjusted. More seeds cannot undo reused/inspected data.

## Official adaptation, without package modifications

The clean official checkout is pinned to
`6bbd52528bee4936786ff0e9eb8a569698b1c731` (package version .2.3).
Subprocesses invoke its `experiments/run_mntp.py` and `run_simcse.py` unchanged;
we supply model, data and hyperparameter JSONs. Installed LLM2Vec remains the
official .2.3 package in the separate encoder environment.

Training text is generated solely from the selected training questions and saved
sampled answers, never validation/test text or reference answers. Convert to
128-token windows whose decoded/stripped text re-tokenizes to exactly 128 tokens.
MNTP groups fixed-length blocks; SimCSE uses the official `Wiki1M` **text-file
loader** pointing to our math corpus (no Wikipedia data). Equal lengths avoid
variable padding in adaptation batches; critic extraction remains unpadded.

Both stages use LoRA rank 16, LR 3e-5, BF16, FlashAttention-2, batch 2 with gradient
accumulation 4 and gradient checkpointing, seed 42. Main runs 500 optimizer steps
per stage; smoke two. MNTP masks .2 of tokens; SimCSE uses dropout .3 and loss
scale 20. These are declared initial budgets, not tuned optima or exact paper
hyperparameters. Accumulation does not enlarge SimCSE's in-batch negative pool.
MNTP merges into a new frozen base before SimCSE; final SimCSE adapter is merged
into a new encoder checkpoint. Original Qwen weights remain untouched.

The selected encoder and SLICE must remain fixed before any future cumulative
online matrices are started. Every extracted backbone must pass the actual
attention-dependence probe and repeatable unpadded feature extraction.

## Run the smoke first

After pushing v5, with no jobs relying on an older checkout still running:

```bash
cd /usr/xtmp/ms785/rl_ms_project
git switch v5
git pull --rebase origin v5
source scripts/cluster_env.sh
bash tools/encoder/fetch_official.sh

python3 tools/encoder/submit_study.py --mode smoke \
  --out outputs/encoder-offline-smoke-v1
```

No reinstall of .venv-encoder is required. Source and passed-sanity defaults are
the paths above and `outputs/encoder-sanity-v2`. The clean official checkout is
under ignored `third_party/llm2vec`; it is not a fork or copied implementation.

Five stages: prepare → adapt → extract (three-arm array) → fit → evaluate. Each
job requests one A5000, four CPUs and 48 GB; extraction allows three concurrent
jobs. Even CPU-heavy fitting uses the GPU partition to avoid the CPU queue;
allocated GPU time is not utilization. No full training launches automatically.

```bash
cat outputs/encoder-offline-smoke-v1-submission/jobs.tsv
cat outputs/encoder-offline-smoke-v1/verification.json
cat outputs/encoder-offline-smoke-v1/report.txt
```

On failure, inspect the relevant `*-submission/logs/*.out` and `mntp.log` or
`simcse.log`. Use a new output name for a new attempt; automatic resume is not
implemented. Ambiguous submission stops the chain; check Slurm before retrying.

After reviewing a passed smoke, submit main explicitly:

```bash
python3 tools/encoder/submit_study.py --mode main \
  --smoke outputs/encoder-offline-smoke-v1 \
  --out outputs/encoder-offline-numina-v1
```

Do not change code/data/environments while these jobs run. Main checks smoke
identity and unchanged implementation before submitting. Final report gives
equal-question raw Brier, per-seed numbers, paired exploratory intervals and
extraction time. Adaptation timings and hashes live in `adaptation.json`; fit
timings in each arm/fit-SEED/fit.json. Extraction times include feature writes,
exclude encoder loading; adaptation times include training/export. Prior
generation, source training, setup and failed allocations are additional costs.

## Validation performed locally

Official MNTP/SimCSE argument parsers accepted generated configs. Targeted CPU
tests check training-only corpus, fixed-length blocks, shared original SLICE fit,
no test rows in Ridge, one raw-sum head and Slurm dependencies. Full GPU training
and adapted-checkpoint restoration remain cluster-smoke checks, not completed
local results. See [encoder foundation](ENCODER_CRITIC.md) for the earlier actual
Qwen attention gate and the still-unapproved padded-batch path.
